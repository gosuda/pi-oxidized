- Keep exactly five root workspace crates with these dependency edges only: `pi-agent -> pi-ai`, `pi-ext -> {pi-ai, pi-agent, pi-tui}`, and `pi -> {pi-ai, pi-agent, pi-ext, pi-tui}`; `pi-ai` and `pi-tui` must have no workspace dependencies. This topology preserves the provider, agent, extension, terminal, and product ownership boundaries.
- Add a dependency only with its first callsite, after rechecking the current crate release and upstream repository for maintenance, yank status, and an allowed license. Check the latest stable version of each crate then pin it exactly (`=x.y.z`), as every existing manifest does, and enumerate only the features actually used, disabling default features when they pull in dead weight. This prevents speculative edges and stale or unusable pins, and keeps upgrades deliberate manifest edits.
- Keep `pi-tui` product-agnostic. Terminal components must remain reusable without provider, agent, extension, or product policy.
- Keep the canonical UI value types in `pi_tui::layout` (`SizeValue`, `OverlayAnchor`, `OverlayMargin`, `OverlaySpec`). `pi-ext/src/protocol.rs` holds deliberately local wire copies so protocol validation never depends on pi-tui compile health; a change to either side must update both, keeping field names and JSON shapes in lockstep.
- Keep `pi-ext` the single authority for the JSONL extension envelope; `packages/pi-tui-protocol` is a portable protocol client, never a second authority. `packages/pi-tui-protocol/tests/fixtures/frames.jsonl` is the shared wire-contract witness consumed by both the Rust protocol tests (`include_str!`) and the TypeScript codec tests, so a codec change must update the fixture and keep both suites green in the same change.
- Keep Bun out of built-in provider requests and native paint. Bun is permitted only in the bundled TypeScript extension host and extension-defined custom providers so native operation does not inherit host latency or availability.
- Keep terminal input on the native fast path when no extension handler exists. When interception is active, bound the cross-process wait, fail open, and disable TypeScript handlers after a timeout or throw so one plugin cannot stall current or later keystrokes.
- Serialize extension bind and reload through the same outer lifecycle lock. Prepare the replacement host and restore flag values before commit, and leave the current host live when preparation fails, so lifecycle operations cannot interleave or expose a half-reloaded host.
- Preserve TypeScript plugin compatibility with `.references/pi/packages/{ai,agent,coding-agent,tui}` rather than object-order or implementation identity. Those four packages are the authority for serialized names and observable contracts.
- Never hand-edit generator-owned artifacts: `crates/pi-ai/data/builtin-models.json` and everything under `.agent-tasks/pi-rust-rewrite/fixtures/` are emitted by `scripts/generate-*.ts`. Regenerate with the owning script, and keep the generators offline-deterministic; network fetches are forbidden.
