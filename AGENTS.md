- Keep exactly five root workspace crates with these dependency edges only: `pi-agent -> pi-ai`, `pi-ext -> {pi-ai, pi-agent, pi-tui}`, and `pi -> {pi-ai, pi-agent, pi-ext, pi-tui}`; `pi-ai` and `pi-tui` must have no workspace dependencies. This topology preserves the provider, agent, extension, terminal, and product ownership boundaries.
- Add each dependency only with its first callsite, after checking the current stable release. Pin it exactly (`=x.y.z`), enumerate only the features used, and disable default features that pull in dead weight. This prevents speculative edges and stale pins while keeping upgrades deliberate.
- Keep `pi-tui` product-agnostic so terminal components remain reusable without provider, agent, extension, or product policy.
- Keep the resolved UI layout values in `pi_tui::layout` (`SizeValue`, `OverlayAnchor`, `OverlayMargin`, `OverlaySpec`) and their intentional wire-local counterparts in `pi-ext/src/protocol.rs`. Preserve `OverlayMarginWire`'s scalar-or-object round trip and convert it only through the explicit adapter; protocol validation must not depend on `pi-tui` compile health.
- Treat `pi-ext/src/protocol.rs` as the authority for the extension JSONL envelope and `packages/pi-tui-protocol` as its portable TypeScript mirror. Preserve `packages/pi-tui-protocol/tests/fixtures/frames.jsonl` as the shared cross-language wire witness so the mirror cannot become a competing protocol authority.
- Keep Bun out of built-in provider requests and native paint. Bun is permitted only in the bundled TypeScript extension host and extension-defined custom providers so native operation does not inherit host latency or availability.
- Preserve observable TypeScript extension compatibility with `.references/pi/packages/{ai,agent,coding-agent,tui}`; match serialized names and behavior, not JavaScript object order or implementation identity. Treat the source-pinned reference as read-only because those packages define the compatibility target.
- Never hand-edit generator-owned artifacts: `crates/pi-ai/data/builtin-models.json`, `crates/pi/tests/fixtures/sessions/`, and `crates/pi/tests/fixtures/tool-schemas/`. Regenerate each with its owning `scripts/generate-*.ts` script, and keep generation offline-deterministic because network input would make checked-in model and protocol witnesses irreproducible.
- Treat Rust as the trust boundary for extension-rendered UI: pass every inbound `UiSlot` through `pi_ext::sanitize` and render only `SanitizedSlot`; never paint raw extension bytes. Extensions can split terminal control sequences across runs or generations, so TypeScript structure alone is not safe.
- Preserve the handshake asymmetry: Mode 1 TypeScript-compat hosts validate both `protocolVersion` and `compatibilityVersion`, while Mode 2 lean and Mode 3 native endpoints validate only `protocolVersion`. Lean and native endpoints do not expose the pinned TypeScript runtime, so requiring its compatibility version would reject valid endpoints.
- Resolve the TypeScript extension host only from `PI_EXTENSION_HOST` or sibling packaged assets; never search `PATH` or fall back to another executable. This prevents accidental or attacker-controlled host selection.
- XC-1: TypeScript extension compatibility contract (docs/extension-compatibility-contract.md) defines the settled serialized-and-observable extension boundaries.
